# Givezy: project rules

- The build brief is the source of truth; `docs/decisions.md` records changes and open questions. `docs/go-live-checklist.md` is the go-live list: update it whenever a new go-live step or open decision comes up, and bring it up when go-live is discussed.
- Money is integer cents (bigint) in ZAR. Percentages are integer ppm. Never floats.
- Fee, VAT, minimum and tax-year values live only in `src/config/platform.ts`.
- Display: `R1 250` and `R30` (no cents when they are zero), `R34.57` when there are cents, dd/mm/yyyy, SA English, Johannesburg time.
- Never invent a fee or rate. Gateway rates stay null until Yehuda supplies them.
- Nothing outside the gateway adapter may reference a specific gateway.
- Every table has row-level security. Money and receipt writes are server-only (service role).
- Hebrew text: `lang="he" dir="rtl"`. Check pages at 375px wide.
- Brand: Givezy (renamed from Nadiv Lev, 15/10/2026; the company is Givezy). The name is always "Givezy". Website, app, emails and receipts share one look, v2 (decided 16/10/2026): white pages (#FFFFFF); logo blue (#1749B5) for headlines, buttons, tabs and big colour-block sections, with white text on it; deep navy (#092577) for headlines on light grounds, body text on lilac and the 4px "pressable" edge under buttons; orange (#FF914D) for one call to action per screen, splashes, goal rings and streaks, with navy text on it, never white; soft lavender (#C9B4FA), light purple (#E5D9FF, card borders and ring tracks), pale lilac (#F2ECFF, soft cards) and peach (#FFEBDD, background splashes only); slate (#34466A) for secondary text; sage for the s18A tick. Fredoka (600) for headlines, DM Sans (400 to 700) for everything else, Heebo for Hebrew. Big soft corners (18 on buttons), buttons with a solid bottom edge. Colours live only in `src/app/globals.css` (website), `apps/mobile/src/theme/tokens.ts` (app) and `src/lib/brand-colors.ts` (receipt PDFs and emails, which cannot read CSS variables); change all three together. The website keeps its colour variable names (`--indigo` is the headline colour, `--brand` buttons and links, `--coral` the accent, `--honey` the soft highlight). Sentence case, no all-caps buttons, no exclamation marks. Write "s18A receipt".
- **Evidence of quality** (Yehuda, 18/10/2026). Every screen, on the website, in the app and on the dashboard:
  - **Un-glamorous moments first.** Always show system status (saving, sending, waiting for the payment provider, offline, last updated). Offer undo where an action can be taken back, and ask first on the page where it can't. Recover from errors in plain words: what went wrong, what was kept, and what to do now.
  - **One product, not a pile of screens.** The same thing has the same name, label, button, colour and pattern everywhere (for example "s18A receipt", "monthly donation", "Undo", "Try again", Rand and date formats). Moving between states (loading, empty, error, done) feels the same on every screen. After an action, the dashboard's pattern applies: what just happened, take it back, what next.
  - **Service recovery.** A failed payment, a declined card, a lost connection or an outage gets as much care as success: say it plainly, say what did and didn't happen ("nothing was charged"), keep what the person typed, give one clear next step, and a way to reach a person.
  - **Edge cases are designed, not left over.** Empty states, error states, offline, slow networks, empty or silly input, very long names, zero and huge amounts: each is designed with the same care as the success screen.
  - **Test and break before calling it done.** Use it as a real person would, with Wi-Fi off, empty fields and a declined card, and fix what breaks.
- Run `npm test`, `npm run typecheck` and `npm run lint` before committing. `npm test` starts the local test database if it is stopped, and refuses to run (one plain message) if it still can't reach it, so a green run always includes the database checks. `npm run test:no-db` is only for a machine with no local database.

# Phone app (apps/mobile)

- **The phone app is Givezy** (renamed from Nadiv Lev, 13/10/2026), like the website, in the v2 look (16/10/2026, see Brand above): white pages with soft lilac and peach background splashes, blue colour-block headers with orange and lavender splashes bleeding off the edges, pressable buttons, goal rings, photo story cards for charities, Fredoka headlines, DM Sans body, Heebo for Hebrew. The logo's splash (`src/components/splash.tsx`): the lilac, orange and blue shapes are images cut from the logo, never redrawn, and always all three together when used as the mark. Colours live only in `apps/mobile/src/theme/tokens.ts`. The deep link scheme (`nedivlev://`) and storage keys (`nediv-lev.*`) are unchanged on purpose: renaming them would break the website's return link and people's saved data.

- Expo + Expo Router (routes in `apps/mobile/src/app`). Donor-facing; charity and admin screens stay on the website.
- Brand tokens live only in `apps/mobile/src/theme/tokens.ts`. Follow `apps/mobile/AGENTS.md` for Expo rules.
- The app never handles card details and has no card fields. Once-off gifts can be started in the app (decided 14/10/2026): the give screen (`apps/mobile/src/app/give/[slug].tsx`) takes the amount, giving kind, optional contribution and donor details, then calls our server (`/api/app/quote`, `/api/app/checkout`, which reuse the website's `quoteDonation`/`startDonation`), and the card is entered on the payment provider's own page in an in-app sheet. A gift is only paid when the provider confirms it. Two switches, both off by default: `EXPO_PUBLIC_IN_APP_GIVING=yes` in the app and `APP_GIVING=yes` on the server. Off, "Give on our website" opens the phone's browser. Keep both off in store builds until Apple and Google have confirmed in writing that this is allowed (see `docs/go-live-checklist.md`). Monthly giving works the same way (the "Give every month" switch on that screen). Never name a specific gateway in app copy.
- **First open is "small yes first"** (decided 20/10/2026): welcome, two skippable questions (kind of giver, causes), then Discover with those causes first. The goal is asked about once, after a first confirmed gift ("Make it a habit": Set my goal / Maybe later), with a dismissible goal card on Home. Never invent an impact line or number; no guilt wording, no repeat pop-ups. Goals count the tax year. Details in `docs/decisions.md`.
- The files the app shares with the website stay dependency-free: `src/lib/money.ts`, `fees.ts`, `sa-id.ts`, `policy.ts`, `glossary.ts`, `charity/initials.ts`, `charity/suggested-amounts.ts`, `charity/impact.ts`, `donations/labels.ts`.
- Review screenshots: `npx expo export --platform web`, serve `dist`, open with `?preview=iphone`.
