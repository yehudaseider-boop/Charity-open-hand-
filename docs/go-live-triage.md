## How this file works

The checklist is now 452 lines and 277 open items. Every item carries its line number in `docs/go-live-checklist.md` and its own bold title so it can be found; items with no bold title start with their opening words in quotes. Some items are duplicates of each other; they are placed on their own merits and point to the twin.

Placement rules used:

- A migration whose next step is Yehuda's yes for the test database goes in list 1. A migration already on the test database, where only the live step is left, goes in list 2. Where the item also has a wording approval or decision for Yosef or Yehuda, it stays in list 1 and its migration is still named in the live order below.
- Account steps, cost approvals, wording approvals, real-device checks and decisions are list 1. Settings and flags that only need flipping on a system that already exists, at launch, are list 2.
- Items marked [Paystack] only matter if Paystack is the provider at launch. They stay in list 1 where placed (see the cross-cutting question under Unclear).
- Where an item and its twin disagree about whether something was applied on the test database, the item is placed on its own words and the conflict is stated.
- Work that only Claude can do (build, fix) is listed in list 1 with "Claude" as the who, because it still needs Yehuda's go.
- I did not query the live or test database; "applied on test" is what the checklist says, not something I checked.
